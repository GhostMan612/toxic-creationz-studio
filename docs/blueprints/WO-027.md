## 0. Reference: What Tagger's GhostBot Is (Do Not Re-Invent It)

Tagger's Ghost (`lib/widgets/ghost_chat_overlay.dart`, GhostBrain T4–T6) is a chat overlay that answers questions from local knowledge, offers one-line help chips (dismissible, never an auto-action), keeps memory on-device only with a one-tap "Forget what you've learned", keeps proactive behaviour default OFF, and speaks in a dry/sarcastic/happy Ghost voice. The Toxic Ghost Tutor copies that contract and adds one thing Tagger cannot do: it runs inside the DAW, so it can **act** on the session through the same code paths the RPC handlers use — always behind a confirm chip, never on its own.

## 1. File-by-File Implementation Scope

### A. Ghost Tutor Panel (`src/GhostTutorComponent.h/.cpp` [New], `src/MainComponent.h/.cpp`, `CMakeLists.txt`)
Create a toggleable `"Ghost"` dockable panel (`GhostTutorComponent`) inside `MainComponent`, following the existing member-dock pattern (`MidiKeyboardDock`, `ScriptPrompterComponent`):
1. **Chat surface:** Scrollable transcript (`juce::ListBox` or `TextEditor` log), single-line input + Send button, Enter-to-send. Dark studio theme via `StudioLookAndFeel`, `juce::FontOptions` everywhere. Add a `"GHOST"` header toggle button (painted with a tiny vector-drawn monochrome ghost glyph — **no color emoji characters** like `👻` that render as missing-glyph boxes on Windows JUCE) in the two-row studio header; panel open/closed state persists in `te::Edit` `ValueTree`.
2. **Offer chips:** After an answer, Ghost may show at most one follow-up chip (`"Want me to do it for you?"`) — dismissible, never an auto-action, never a chain. Chips are `juce::TextButton`s in a chip row under the transcript.
3. **Confirm-before-act:** Every mutating action Ghost proposes (create track, arm recording, insert plugin, patch rack, run BGM) renders as a chip with the exact action in plain words (`"Create a 4-track session at 124 BPM"`). Nothing executes until the operator taps the chip. Read-only answers never need a chip.

Each section: what it is, where the button lives, 3–5 steps, matching RPC/MCP tool name. Keep under ~400 lines.
2. **Packaging & Embedded Fallback:** Update `scripts/package-windows.ps1` to copy `docs/GHOST_KNOWLEDGE.md` into the Windows zip, **and** embed a compiled fallback copy (via `juce_add_binary_data` or embedded raw string in `GhostKnowledge.cpp`) so Ghost still works seamlessly if `Toxic Creationz Studio.exe` is moved standalone.
3. **Deterministic fallback matcher (`GhostKnowledge`):** Keyword/synonym match over the bundle sections (zero dependencies, zero model). Used whenever Ollama is unreachable — Ghost must never hard-fail and never phone home. Fallback answers cite the bundle section they came from.

### C. Local Ollama Brain (`src/GhostBrain.h/.cpp` [New])
1. **Cross-platform localhost HTTP/1.1 client (`juce::StreamingSocket`):** Use a lightweight raw HTTP/1.1 `POST` over `juce::StreamingSocket` to `127.0.0.1:11450/api/chat` (Glenn's established Ollama port; never `11434`) so it works identically on Windows, macOS, and Linux even with `JUCE_USE_CURL=0`. Default model `qwen2.5:3b`, fallback `phi4-mini` on model error.
2. **Split Timeouts & Async Safety:**
   - Run all socket I/O on a **background thread** (never blocking the JUCE message thread), marshaling replies back via `juce::MessageManager::callAsync` guarded by `juce::Component::SafePointer<GhostTutorComponent>`.
   - Use a **1.5 s TCP connect timeout** (fail fast when Ollama is offline — never stall 60 s), a **30 s read timeout** only *after* TCP connect succeeds, and one retry on transient read error before falling back cleanly to `GhostKnowledge` (`"Ollama is down — answering from the built-in guide."`).
   - Skip all socket calls completely when `--smoke-test` is active or `use_llm: false`, routing straight to `GhostKnowledge`.
   - `~GhostBrain()` / `~GhostTutorComponent()` MUST cancel and join any in-flight background request before destruction (ASAN-clean teardown).
3. **Prompt construction:** System prompt fixes Ghost's voice (dry, a little sarcastic, helpful, `"Boo."` sparingly) and ground rules (answer only from the knowledge bundle + live session state; never invent a button, menu, or shortcut). User prompt carries the question, top 2 matching bundle sections, and a compact live-session snapshot (track count + names, armed track, BPM, loop range, selected clip) read directly from `te::Edit`.
4. **No cloud, no external network.** Localhost `127.0.0.1` only; lives strictly in desktop `AIDAW`.
